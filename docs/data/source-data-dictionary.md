# StatsBomb source data dictionary

This dictionary is the canonical source-field register for the audited local
StatsBomb Open Data snapshot. It combines the bundled official specifications
with exhaustive observation of every JSON object, array container, array item,
and leaf path. It does not describe a normalized ScoutLabs schema.

## Evidence and scope

- Audit artifact: `reports/snapshot-audit.json`; manifest
  `676857cc079ceb4a0aa5369e01be762544dc76451720a9bb818e3d45eb5f09cb`.
- Audit UTC: `2026-07-24T19:52:53.244431+00:00` to
  `2026-07-24T20:16:10.316470+00:00`.
- Provider snapshot commit:
  `b0bc9f22dd77c206ddedc1d742893b3bbe64baec`.
- Physical schema universe: 8,977 files and
  14,874,171 event records, including
  274 event/lineup files not referenced by a valid match record.
- Analytical grouping universe: 3,961 unique valid `match_id` records and
  13,911,986
  events. Field occurrence counts below use the complete physical universe;

- “Documented” refers only to the six bundled PDF specifications. “Observed”
  refers to this exact local snapshot. Provider-supplied does not imply
  analytically validated.

Documented-only fields in this register are
`events[].half_end.match_suspended`, `lineups[].lineup[].player_gender`, `lineups[].lineup[].player_height`, `lineups[].lineup[].player_weight`. The bundled
data-version 1.1 change log names lineup gender, height and weight, but its
lineup table does not state their JSON types; the dictionary preserves that
ambiguity rather than inventing types.

The requirement column uses exactly one presence class per row. “Required”
means the file or parent structure requires the key (a nullable value can still
be present); “Optional” means the bundled specification permits omission or
does not establish a mandatory contract; “Conditional” means the row exists
only when its parent array, event family, or true-only context applies.

Observed-only extensions/legacy representations are:
`competitions[].competition_international`, `competitions[].competition_youth`, `competitions[].match_available_360`, `competitions[].match_updated_360`, `events[].clearance.head`, `events[].clearance.left_foot`, `events[].clearance.other`, `events[].clearance.right_foot`, `events[].pass.inswinging`, `events[].pass.no_touch`, `events[].pass.outswinging`, `events[].pass.straight`, `events[].shot.kick_off`, `lineups[].lineup[].cards`, `lineups[].lineup[].cards[]`, `lineups[].lineup[].cards[].card_type`, `lineups[].lineup[].cards[].period`, `lineups[].lineup[].cards[].reason`, `lineups[].lineup[].cards[].time`, `lineups[].lineup[].positions`, `lineups[].lineup[].positions[]`, `lineups[].lineup[].positions[].end_reason`, `lineups[].lineup[].positions[].from`, `lineups[].lineup[].positions[].from_period`, `lineups[].lineup[].positions[].position`, `lineups[].lineup[].positions[].position_id`, `lineups[].lineup[].positions[].start_reason`, `lineups[].lineup[].positions[].to`, `lineups[].lineup[].positions[].to_period`, `matches[].last_updated_360`, `matches[].match_status_360`, `matches[].metadata.shot_fidelity_version`, `matches[].metadata.xy_fidelity_version`. These paths require a
provider-version decision before normalization.

`events[].pass.through_ball` is both documented and observed but deprecated in
data version 1.1. The replacement representation is
`events[].pass.technique` with Through Ball as a value. Legacy Camera On and
Camera off event types are likewise deprecated but still observed; see
[event taxonomy](event-taxonomy.md).

### Denominator policy

Event-specific object fields use their physical event-type count, including
nested object members such as `pass.outcome.id`. Repeated array-item fields use
the observed item population. `events[].counterpress` is the important
flattened exception: its denominator is the documented eligible-family
population, not all events. General event fields whose exact applicability
cannot be determined without a semantic policy retain the all-event population
and are explicitly optional-by-applicability; their percentage must not be read
as a missing-data rate.
