# Data-quality framework

**Framework version:** 0.1.0  
**Scope:** StatsBomb Open Data source and proposed ScoutLabs normalization  
**Status:** Proposed rules with completed checks linked explicitly to
[validation records](../research/validation-results.md)

The rules distinguish provider defects, expected conditional absence, partial
coverage, and unresolved analytical assumptions. A missing optional field is not
an error merely because it is absent. Validation must use the documented and
observed applicability denominator in the
[source dictionary](source-data-dictionary.md).

## Severity policy

| Severity | ScoutLabs response |
|---|---|
| Blocking | Stop the affected ingestion unit; do not publish dependent metrics or model outputs. Preserve the source path, error, and audit version. |
| Error | Quarantine or exclude the affected record or relationship from dependent calculations. Continue independent units and report the count. |
| Warning | Retain the record only with an explicit quality state; suppress outputs whose interpretation would become misleading. |
| Information | Preserve for provenance, coverage, or interpretation; no automatic exclusion. |

## Playing-minutes decision boundary

No complete playing-minutes algorithm is validated here. Three approaches remain
under [EXP-MIN-001](../research/metric-experiments.md):

1. construct intervals from Starting XI, Substitution, Player On, Player Off,
   dismissal, and actual period endpoints;
2. use the observed lineup `positions[]` intervals as provider-derived evidence,
   then reconcile them with events;
3. combine both, preferring independently consistent evidence and producing an
   unresolved state on conflict.

The combined approach is the strongest candidate, but stoppage time, extra time,
shootouts, dismissals, incomplete video, unusual tactical-shift intervals, and
provider-observed period fields must be validated before
`MET-AVAIL-MINUTES` can advance beyond **Proposed**.
